STM32F407 ile Buton Okuma ve Debounce: Register Seviyesinde İlk Adım

Gömülü sistemlerde bir sonraki adımım STM32: endüstride de öğrenci takımlarında da (kısa süre önce katıldığım AGÜ Roket Takımı dahil) en sık karşılaşılan mikrodenetleyici ailelerinden biri. Bu yüzden STM32'yi temelden, gerçekten anlayarak öğrenmeye karar verdim ve öğrendiklerimi burada bölüm bölüm kaydediyorum.

Arduino'daki digitalRead() gibi hazır fonksiyonlar yerine register seviyesinde başlıyorum: hangi bit neyi yapıyor, referans kılavuzdan (RM0090) bakıp kendim yazıyorum. Kart STM32F407G-DISC1, geliştirme ortamı Keil µVision. İlk uygulama: kartın üzerindeki butonu okuyup LED'leri sürmek.

Görev

Başlangıçta turuncu ve mavi LED yanar. Butona her basışta yeşil ve kırmızı yanar, bırakınca turuncu ve mavi geri döner. 3 geçerli basıştan sonra program ikinci aşamaya geçer ve dört LED birlikte yanıp söner. Kulağa basit geliyor ama asıl ders, “geçerli basış” kelimesinde saklı.

Donanım: kartın üzerindeki buton ve LED'ler

Mavi USER butonu (B1) PA0 pinine bağlı ve aktif-yüksek: basınca pin 1, bırakınca 0 okunuyor. Kartta harici bir pull-down direnci olduğu için PA0'ın dahili pull-up/pull-down dirençlerini kapalı bıraktım. Dört LED ise PD12–PD15 pinlerinde, kartın ortasında bir artı şeklinde diziliyor. Karşılıklı duran yeşil–kırmızı çiftine CROSS_A, turuncu–mavi çiftine CROSS_B adını verdim.

Adım 1: Saatleri aç (RCC)

STM32'de güç tasarrufu için çevre birimlerinin saati varsayılan olarak kapalıdır; GPIO portuna yazmadan önce saatini açmak gerekir. GPIOA ve GPIOD, AHB1 veriyolunda. RCC_AHB1ENR register'ında bit 0 GPIOA'yı, bit 3 GPIOD'yi açıyor.

RCC->AHB1ENR |= (1U << 0) | (1U << 3);   // GPIOA + GPIOD saati

Adım 2: Pin modlarını ayarla (MODER, PUPDR)

MODER register'ında her pine 2 bit düşer. Önce iki biti &= ~(3U << (i*2)) ile temizleyip sonra |= (1U << (i*2)) ile “01” yazıyorum; temizlemeden yazarsam önceki değer karışabilir. PA0'ın modu “00” (giriş) kalıyor.

Adım 3: LED'leri BSRR ile sür

LED'leri ODR yerine BSRR (bit set/reset) register'ıyla yakıp söndürüyorum. Alt 16 bit pini 1 yapar, üst 16 bit 0 yapar; 0 yazılan bitler hiçbir şeyi değiştirmez. Böylece tek bir yazmayla bazı LED'leri yakıp bazılarını söndürebiliyorum ve oku-değiştir-yaz yapmama gerek kalmıyor; işlem atomik.

Sorun: bir basış, birden fazla sayım (bouncing)

İlk denemede tek basışın birden fazla basış gibi algılandığını gördüm. İlk başta bunun buton kontakları arasında oluşan bir ark olduğunu düşünmüştüm; asıl sebep ise mekanik: butona bastığında içindeki metal kontaklar birbirine çarpar ve yerine oturmadan önce çok kısa bir süre sekerek birkaç kez açılıp kapanır. Buna kontak sıçraması (contact bounce) deniyor ve çoğu butonda birkaç milisaniye sürüyor.

İnsan için birkaç milisaniye hiçbir şey ama 16 MHz'de çalışan bir işlemci bu sürede pini binlerce kez okuyabilir. Kodun gözünden her sıçrama ayrı bir basış: 3 basışlık hedef tek basışta dolabilir.

Çözüm: oku, bekle, tekrar oku

Çözüm olarak yazılımsal debounce uyguladım: pin 1 okunduğunda hemen sayma, sıçramaların bitmesi için biraz bekle ve tekrar oku. Hâlâ 1 ise bu gerçek bir basıştır. Ardından buton bırakılana kadar bekleyip bırakırken oluşan sıçramayı da atlıyorum; yoksa bırakma anındaki sıçrama yeni bir basış gibi görünebiliyor.

while (count < 3U) {
    if (GPIOA->IDR & BTN) {                 // (1) basis olabilir
        delay(DEBOUNCE);                    // (2) sicramalar bitsin
        if (GPIOA->IDR & BTN) {             // (3) hala basili -> gercek basis
            GPIOD->BSRR = CROSS_A | (CROSS_B << 16);
            count++;
            while (GPIOA->IDR & BTN);       // (4) birakilana kadar bekle
            GPIOD->BSRR = CROSS_B | (CROSS_A << 16);
            delay(DEBOUNCE);                // (5) birakma sicramasini atla
        }
    }
}
Kendin dene
Sanal kart: 3 geçerli basış
0 / 3 geçerli basış
Debounce açıkken her basış bir kez sayılır. Kapatıp tekrar dene.

Simülasyon: debounce kapalıyken her basışta kontak 2–4 kez “sıçrar”.

Neden delay ve sınırları

Bekleme için şimdilik basit bir sayaç döngüsü kullandım: void delay(volatile uint32_t n) { while (n--); }. volatile, derleyicinin bu “hiçbir şey yapmayan” döngüyü optimizasyonla silmesini engelliyor. DEBOUNCE değerini deneyerek ayarladım: çok küçük olursa sıçramalar geçmeden tekrar okunuyor, çok büyük olursa kısa ve hızlı basışlar kaçırılıyor.

Bu yöntemin iki zayıf yanı var: süre, işlemci frekansına ve derleyici ayarlarına göre değişiyor, yani milisaniye cinsinden kesin değil; ve beklerken işlemci başka hiçbir iş yapamıyor. Aynı anda sensör okuyan ya da haberleşme yapan bir projede, butonu beklemek için işlemciyi kilitlemek kabul edilemez. Bunun daha iyi yolları var: SysTick ile gerçek milisaniye zamanlaması ve butonu EXTI kesmesiyle okumak.

Kodun tamamı
#include "stm32f4xx.h"

#define BTN       (1U << 0)                     // PA0
#define CROSS_A   ((1U << 12) | (1U << 14))     // yesil + kirmizi
#define CROSS_B   ((1U << 13) | (1U << 15))     // turuncu + mavi
#define LED_ALL   (CROSS_A | CROSS_B)           // PD12-15
#define DEBOUNCE  30000U                        // fazla olursa kisa basislari kacirir
#define BLINK     300000U

void delay(volatile uint32_t n) { while (n--); }

int main(void)
{
    uint32_t i;
    uint32_t count = 0;                          // gecerli basis sayisi

    RCC->AHB1ENR |= (1U << 0) | (1U << 3);       // GPIOA + GPIOD saati
    GPIOA->MODER &= ~(3U << (0 * 2));            // PA0 giris
    GPIOA->PUPDR &= ~(3U << (0 * 2));            // PA0 pull yok (kartta pull-down var)
    for (i = 12; i < 16; i++) {
        GPIOD->MODER &= ~(3U << (i * 2));        // PD12-15 temizle
        GPIOD->MODER |=  (1U << (i * 2));        // PD12-15 cikis
    }

    GPIOD->BSRR = CROSS_B | (CROSS_A << 16);     // baslangic: buton birakili durumu

    while (count < 3U)
    {
        if (GPIOA->IDR & BTN) {                  // (1) basis olabilir
            delay(DEBOUNCE);                     // (2) sicramalar bitsin
            if (GPIOA->IDR & BTN) {              // (3) hala basili -> gercek basis
                GPIOD->BSRR = CROSS_A | (CROSS_B << 16);
                count++;
                while (GPIOA->IDR & BTN);        // (4) birakilana kadar bekle
                GPIOD->BSRR = CROSS_B | (CROSS_A << 16);
                delay(DEBOUNCE);                 // (5) birakma sicramasini atla
            }
        }
    }

    /* --- 2. asama: hepsi yanip sonsun --- */
    while (1)
    {
        GPIOD->BSRR = LED_ALL;                   // BS12-15 -> hepsi yanar
        delay(BLINK);
        GPIOD->BSRR = LED_ALL << 16;             // BR12-15 -> hepsi soner
        delay(BLINK);
    }
}

Teknik detaylar

  • Kart: STM32F407G-DISC1 (STM32F407VG, Cortex-M4)
  • Geliştirme ortamı: Keil µVision · Dil: C, register seviyesi (CMSIS başlığı stm32f4xx.h)
  • Kullanılan register'lar: RCC_AHB1ENR, GPIOx_MODER, GPIOx_PUPDR, GPIOx_IDR, GPIOx_BSRR
  • Pinler: PA0 (USER butonu, aktif-yüksek), PD12–PD15 (LED)
  • Kendi devrende LED kullanacaksan seri direnci LED direnci hesaplama aracıyla bulabilirsin.

Bu bölümden aklımda kalanlar

  • Bir çevre birimini kullanmadan önce saatini açmak gerekiyor.
  • MODER gibi çok bitli alanlara yazmadan önce ilgili bitleri temizlemek gerekiyor.
  • BSRR ile pinleri tek yazmada ve güvenle değiştirmek mümkün.
  • Mekanik butonlar “temiz” sinyal vermez; debounce her zaman gerekir.
